## 评分标准

### 及格
* 程序能跑。 Agent 链路是通的——用户输入能走到 LLM 再回来。功能不用全做，核心流程跑起来就行。界面不
挑，命令行也行。
* 文档。 README（项目介绍、谁做的、怎么跑起来）+ .env.example （配置样例，值填假或留空）+ 测试用例
及测试结果（至少 5 组核心流程用例，证明程序真的能跑通）。
* 技术底线。 至少 1 个 @tool 或 1 条 RAG 链路是你自己写的，不是直接复制样例改个名。
* 答辩。 能把项目跑起来演示，说清楚做了什么。提问能答个大概。

### 中等
* 功能做完了。 课题描述的核心功能基本都有。前端搞个界面——Gradio、Streamlit、Flask 都行，别让用户摸代
码。
* 不崩。 空输入给提示，工具挂了给反馈，别直接 traceback 甩脸上。
* 文档。 README + DESIGN（架构图和模块说明）+ REQUIREMENTS（功能列表和用户场景）。
* 技术底线。 至少 2 个工具或 1 条 RAG + 1 个工具。多轮对话有记忆。 .env 管密钥。
答辩。 演示流畅，每个功能都能说清楚为什么这么做。提问基本能答上来。

### 良好
* 用着舒服。 界面布局合理，操作有引导，输出格式干净。边界 case 基本都处理了——范围外老实说不知道、工
具异常能恢复。
* 文档。 中等三份 + DEPLOY（怎么部署、常见坑）+ ANALYSIS（需求分析、用例、流程图）。
* 技术底线。 至少 3 个工具或 2 个工具 + 1 条 RAG。HITL 审批至少一个场景。至少一个中间件。数据清洗过程有
记录——不是你随便扔进去就行。
* 答辩。 表述清楚，架构图能讲明白。对技术选型有判断、对踩过的坑有分析。提问环节有来有回。

### 优秀
* 能拿出去用。 功能完整、界面舒服、有亮点——不是教科书上的标准答案。流式输出、会话历史、多会话隔离这
些细节做了。
* 文档。 良好五份 + SUMMARY（踩了什么坑、怎么解决的、后续怎么改）。
技术底线。 子 Agent 或 MCP Server 至少搞一个。Store 长期记忆。至少一份 Skill 文档。中间件统计 Token。
* 答辩。 讲得清楚，答得到位。对项目有自己的思考——不是背稿子。Demo 环节能展示边界 case 处理和异常恢
复，不光跑 happy path。
