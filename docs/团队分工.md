# 团队分工与目录约定

> 版本：v1.0　|　日期：2026-08-01
> 三人团队按"数据/算法、Agent/LLM、前端/测试/文档"三线并行，目录即所有权边界。

---

## 1. 角色划分

| 角色 | 分工范围 | 核心交付 |
|---|---|---|
| **A · 数据与算法** | 菜品营养库、菜单采集、数据清洗、SQLite schema、推荐评分公式、组合优化算法 | 数据清洗记录、菜品/菜单数据、评分与优化模块 |
| **B · Agent 与 LLM** | LangChain Agent 编排、工具注册、RAG 链路、LLM 适配、中间件、长期记忆、天气 MCP、会话管理 | 完整 Agent 链路、工具与 MCP |
| **C · 前端、测试与文档** | Vue3 界面、趋势图、测试用例、文档整合、Docker 部署、答辩材料 | 界面、测试报告、全部文档 |

---

## 2. 目录所有权矩阵

| 路径 | 所有权 | 说明 |
|---|---|---|
| `backend/data/` | **A** | 菜品/菜单原始数据与清洗脚本（菜品 ≥50 道、5天×3餐） |
| `backend/db/` | **A** | SQLite schema、建表、数据访问层（可换 MySQL） |
| `backend/tools/scoring.py` `optimizer.py` | **A** | 推荐评分公式、组合优化算法（自研核心） |
| `backend/tools/search.py` `record.py` | **B** | 菜品检索、摄入记录工具 |
| `backend/agent/` | **B** | LangChain Agent 编排、子 Agent、会话记忆 |
| `backend/llm/` | **B** | LLM 供应商适配（Ollama 本地 ↔ 云端可切换） |
| `backend/rag/` | **B** | 菜品 RAG 检索链路（自研） |
| `backend/middleware/` | **B** | 日志 / 耗时 / Token 统计中间件 |
| `backend/store/` | **B** | user_profile 长期记忆 |
| `backend/mcp/` | **B** | 天气 MCP Server（mock 为主） |
| `frontend/` | **C** | Vue3 + Element Plus + TS |
| `docker/` | **C**（B 协助 ollama） | Dockerfile / docker-compose.yml |
| `tests/` | **C** | 测试用例与结果（≥5 组核心流程） |
| `docs/` | **C**（A/B 提供素材） | 需求/设计/部署/分析/总结/团队分工 |
| `.env.example` | 公共 | 配置样例（值留空/假值） |

> `backend/tools/` 为 A/B 共享：**A 拥有 `scoring.py` / `optimizer.py`，B 拥有 `search.py` / `record.py`**，避免同文件冲突。

---

## 3. 协同约定

- **git 分支**：`main`（可运行主干）+ 个人分支 `feat/a-*`、`feat/b-*`、`feat/c-*`。
- **每日集成**：每晚合并到 `main` 并跑通测试，**禁止超过 1 天不合并**。
- **REST 契约先行**：C 与 B 第一天定死 API（路径、入参、出参），前端与后端并行不阻塞。
- **schema 唯一来源**：数据库字段以 A 的 `db/schema.sql` 为准，B 的 store/record 工具只读该 schema，改动需通知。
- **密钥规范**：一律走 `../backend/.env`（复制 `.env.example` 填写），不提交真实密钥。
