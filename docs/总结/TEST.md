## 二、正常测试用例（10 条）

### N-01 用户注册 · 登录 · 数据隔离

- **覆盖功能**：FR-09 用户系统、数据隔离（新增）
- **优先级**：P0
- **前置条件**：后端已启动，数据库可写；用户 `userA` / `userB` 未注册
- **测试步骤**：
  1. `POST /auth/register` 注册 `userA`（密码 ≥ 6 位）→ 返回成功
  2. `POST /auth/login` 用 `userA` 登录 → 返回 `access_token` 与用户信息
  3. `GET /auth/me` 携带 token → 返回当前用户信息
  4. 分别以 `userA`、`userB` 登录，各自写入一条饮食记录与一个自定义菜品
- **预期结果**：
  - 注册/登录/`/auth/me` 均 200，`userA` 信息正确
  - `userA` 与 `userB` 的记录、自定义菜品、偏好**互不可见**（接口返回各自数据）

### N-02 菜品营养查询与来源

- **覆盖功能**：FR-01 菜品营养查询、FR-02 营养库建设
- **优先级**：P0
- **前置条件**：营养库已导入（100 道菜）
- **测试步骤**：
  1. 聊天输入「红烧肉热量多少」或调用 `GET /dishes?keyword=红烧肉`
  2. 查看返回的热量、蛋白质、碳水、脂肪、价格、口味、类别
  3. 核对营养来源字段（如《中国食物成分表》）
- **预期结果**：
  - 返回结构完整：热量 / 蛋白 / 碳水 / 脂肪 / 价格 / 类别 / 克重
  - 数值与库内数据一致，来源字段非空（合规要求 NFR-06）

### N-03 偏好设置 + 预算内推荐与理由

- **覆盖功能**：FR-03 菜单入库、FR-04 推荐评分、FR-05 推荐理由、FR-11 偏好设置、FR-13 菜单页
- **优先级**：P0
- **前置条件**：已登录；偏好页可保存预算范围、口味、忌口、健康目标
- **测试步骤**：
  1. 在「偏好与设置」保存：预算上限 15 元、口味清淡、忌辣、健康目标控油
  2. 打开「菜单」页按当天午餐浏览并筛选菜品
  3. 聊天输入「15 元预算，推荐一顿午餐」
  4. 检查推荐结果的预算、荤素搭配与理由
- **预期结果**：
  - 偏好保存后再次打开表单能回显
  - 菜单页可按日期/餐次/价格/营养范围筛选
  - 推荐结果**全部 ≤ 15 元**、无辣、荤素搭配合理，且每条附推荐理由（如"蛋白质达标且不超预算"）

## 三、边界测试用例（10 条）

### B-01 空消息与纯空白

- **覆盖功能**：NFR-01 可用性（空输入提示）
- **优先级**：P0
- **前置条件**：已登录

  1. 聊天输入框输入空字符串直接发送
  2. 输入仅含空格 / Tab 的文本发送
- **预期结果**：
  - 前端给出「请输入内容 / 消息不能为空」类提示
  - 后端接口返回 400，不产生会话、不调用 LLM、不崩溃

---

### B-02 超低预算无匹配

- **覆盖功能**：FR-04 推荐评分、NFR-05 健壮性
- **优先级**：P1
- **前置条件**：营养库价格最低的菜 ≥ 1 元
- **测试步骤**：
  1. 聊天输入「1 元预算，推荐一顿午餐」
  2. 观察 Agent 回复
- **预期结果**：
  - Agent **如实说明**"预算内暂无可推荐菜品 / 需提高预算"
  - 不抛出内部异常、不返回空壳卡片、给出建设性建议

---

### B-03 查询不存在的菜品

- **覆盖功能**：FR-01/02、NFR-05
- **优先级**：P1
- **前置条件**：营养库无"火星炒饭"
- **测试步骤**：
  1. 聊天输入「火星炒饭的热量是多少」
  2. 观察回复
- **预期结果**：
  - Agent 明确表示库中没有该菜，并主动列出相近菜品或引导搜索
  - 不渲染错误的菜品卡片（普通问答不输出卡片 DOM）

---

### B-04 注册重复用户名 / 弱密码

- **覆盖功能**：FR-09、NFR-03 安全
- **优先级**：P1
- **前置条件**：已存在用户 `userA`
- **测试步骤**：
  1. `POST /auth/register` 重复注册 `userA`
  2. 注册密码长度 < 6 的新用户
  3. 注册密码长度 > 128 的新用户
- **预期结果**：
  - 重复用户名返回 **409 用户名已存在**
  - 密码过短返回 **400 密码至少 6 位**；过长返回 400
  - 不创建任何非法用户、不泄露内部信息

### B-05 普通用户越权访问后台

- **覆盖功能**：FR-10、NFR-03 安全
- **优先级**：P0
- **前置条件**：普通用户 `userA` 已登录，`admin` 已登录
- **测试步骤**：
  1. 用 `userA` 的 token 请求 `GET /admin/stats`、`GET /admin/users`
  2. 用 `userA` 尝试 `PATCH /admin/users/{admin_id}`
- **预期结果**：
  - 普通用户访问 `/admin/*` 返回 **403**（前端无「后台管理」入口，接口层也被拒）
  - 即便手工构造请求也无法修改管理员数据

### B-06 会话消息越权读取

- **覆盖功能**：历史会话隔离（新增）
- **优先级**：P1
- **前置条件**：`userA`、`userB` 均已登录且各有会话
- **测试步骤**：
  1. 获取 `userA` 的一个 `session_id`
  2. 用 `userB` 的 token 请求 `GET /sessions/{A的session_id}/messages`
  3. 用 `userA` 的 token 请求同一接口
- **预期结果**：
  - `userB` 读取 `userA` 的会话消息返回**空**（或 404）
  - `userA` 能正常读到自己的消息（本人/无主会话可读，游客兼容）

---

### B-07 饮食记录越权修改 / 删除

- **覆盖功能**：FR-09 数据隔离、FR-06
- **优先级**：P1
- **前置条件**：`userA`、`userB` 均有饮食记录
- **测试步骤**：
  1. 用 `userA` 的 token `PUT /food-records/{B的记录id}` 修改
  2. 用 `userA` 的 token `DELETE /food-records/{B的记录id}` 删除
- **预期结果**：
  - 修改/删除他人记录返回 **404 记录不存在或无权操作**
  - `userB` 的记录数据未被篡改

### B-08 工具 / LLM 异常兜底与流式失败回退

- **覆盖功能**：NFR-05 健壮性、NFR-01
- **优先级**：P1
- **前置条件**：可临时中断 LLM 通道（关闭本地 Ollama / 云端 API 超时）
- **测试步骤**：
  1. 使 LLM 调用失败，发起一次聊天
  2. 观察前端与后端响应
  3. 构造工具层异常场景（如传入非法参数）
- **预期结果**：
  - 返回友好文案「抱歉，系统处理出错，请稍后再试」**而非 traceback**
  - 流式通道失败时前端自动回退非流式，仍能收到回复
  - `/metrics` 能正常记录请求与错误数，进程不崩溃

### B-09 自定义菜品：空数据与越权

- **覆盖功能**：自定义菜品持久化与隔离（新增）
- **优先级**：P1
- **前置条件**：`userA`、`userB` 已登录；`userA` 有自定义菜品
- **测试步骤**：
  1. 新用户进入「我的自定义菜品」管理弹窗
  2. 用 `userB` 的 token 请求 `DELETE /custom-dishes/{A的菜品id}`、`PUT` 修改
- **预期结果**：
  - 空库时表格显示「暂无自定义菜品」，不报错
  - 越权修改/删除他人自定义菜品返回 **404**，他人数据不受影响

### B-10 超长输入与会话列表隔离

- **覆盖功能**：NFR-01/02、会话隔离（新增）
- **优先级**：P1
- **前置条件**：已登录；可构造超长文本
- **测试步骤**：
  1. 发送 5000+ 字符的超长消息
  2. 查看 `GET /sessions` 列表是否只含本人会话
  3. 在同一时间大量创建会话（接近数量上限）
- **预期结果**：
  - 超长输入被正常处理（截断/分段或友好响应），不超时崩溃
  - 会话列表**仅返回当前登录用户自己的会话**，不含他人会话
  - 会话数量超上限时按策略（LRU / 限制）处理，服务稳定
