# SUMMARY — 食堂推荐 Agent 项目复盘

> 复盘文档：踩了哪些坑、怎么解决的、为什么绕了弯路、再做一次会怎么改、后续还能加什么。
> 本文基于完整 git 历史（D1~D10、v1.0.0~v1.3.0，约 120 个 commit）与各阶段测试记录整理。

---

## 1. 项目一句话

一个食堂智能推荐 Agent：用户在聊天界面用自然语言说"今天想吃清淡点、预算 20 以内"，Agent 通过工具链（菜谱搜索、营养评分、克重优化、天气、记录、用户画像）给出荤素搭配的一餐推荐，并持续记忆用户偏好与饮食记录，用趋势页展示营养摄入变化。

技术栈：FastAPI + LangChain + Chroma RAG + SQLite + Vue3/Element Plus，流式 SSE 输出，云端 API / 远程 Ollama 双通道。

## 4. 踩过的坑与解决方案

### 4.1 数据库路径导致 backend/backend 嵌套（最严重的坑）

- **现象**：从 `backend/` 目录启动时，`DB_PATH=backend/data/canteen.db` 被相对解析成 `backend/backend/data/canteen.db`，产生一套"嵌套垃圾库"；登录、记录全部读写到错误数据库。
- **根因**：`.env` 里的 `DB_PATH` 是相对路径，而启动目录（仓库根 vs backend 目录）不一致，路径解析就错位。
- **解决**：`db.py` 统一做绝对化——以仓库根为准加 `backend/` 前缀，否则基于 backend 根解析，两条路径最终指向同一个文件（commit `9c9045c`、`69678a2`）。
- **反思**：路径问题应该在写配置解析的第一天就确定"单一基准目录"，而不是等出现两份数据库才发现。

### 4.2 .env 加载路径错误导致定位/天气失效

- **现象**：`/location`、天气工具报错，定位总失败。
- **根因**：`location.py`、`weather_data.py` 里的 `load_dotenv()` 用的是项目根相对路径，而 `.env` 实际在 `backend/.env`，导致读不到 `WEATHER_API_KEY`。
- **解决**：统一 load_dotenv 路径指向 `backend/.env`；客户端 IP 提取支持 `X-Forwarded-For`/`X-Real-IP` 并过滤私有/回环地址；新增 `lng/lat` 逆地理编码；前端再加 `navigator.geolocation` 浏览器定位兜底（commit `cbe7e78`、`62f6816`）。
- **反思**：环境变量加载这件事应该收敛到一个模块统一处理，分散在多个文件里就埋了雷。

### 4.3 老库迁移 bug

- **现象**：从 v1.0 老库升级到 v1.1.0（新增用户表等列）时迁移报错。
- **根因**：迁移逻辑假设旧表结构固定，对"中间态"数据库（加过部分列）不幂等。
- **解决**：v1.1.0 发布时重构迁移代码，每次只对缺失项做增量操作（commit `ba43a29`）。
- **反思**：迁移必须幂等，且要有"从任意历史版本升级"的测试。

### 4.4 upsert 丢字符 / 画像不生效 / 优化器偏好失效

- **现象**：偏好保存后字符丢失；推荐时忽略画像；优化组合不遵守口味偏好。
- **根因**：`upsert` 拼 SQL 时字段顺序/字符处理错误；`recommend` 没把 profile 注入工具参数；optimizer 只按预算不按偏好过滤。
- **解决**：统一 `upsert_user_profile` 的字段写入；recommend 链路透传画像；optimizer 增加偏好约束（commit `7cf9231`）。
- **反思**：数据流（DB → Store → 工具 → LLM 上下文）每一跳都要有测试断言，不能只测两端。

### 4.5 RAG 结果不确定 / 缓存失效

- **现象**：同一问题两次检索结果不一致；RAG 缓存命中率低。
- **根因**：Chroma 集合固定但未做确定性哈希；缓存键不稳定。
- **解决**：检索结果用确定性哈希；`get_db` 改延迟绑定避免循环导入（commit `c8a8c27`、`986ddde`）。
- **反思**：缓存键必须由"输入+参数"完全决定，否则缓存等于摆设。

### 4.6 工具异常裸奔 / 子 Agent 崩溃

- **现象**：工具抛异常直接 500，前端看到 traceback。
- **解决**：工具层统一兜底（返回友好错误文案）、子 Agent 失败自动降级到主 Agent、LLM 超时重试、`token_history` 限长（commit `986ddde`、`fd22aa2`）。
- **反思**：边界兜底（评分标准"不崩"档）应该和主功能同时做，不能等答辩前补。

### 4.7 流式输出两次返工

- **现象**：第一版"流式"是模拟逐字吐出，不是真流。
- **解决**：改用 `agent.astream_events()` 实现真实 token 流（commit `6f7efc5`），前端 SSE 逐字渲染 + 光标动画 + AbortController 中断 + 流式失败回退非流式。
- **反思**：应该一开始就确认"真实流式"是亮点项，直接上 astream_events，而不是先做个假的。

### 4.8 LLM 无限输出占满远程服务器 slot

- **现象**：远程 Ollama（119.45.135.201）上模型偶发无限输出，占满并发 slot，后续请求全排队超时。
- **解决**：ollama.service 加 `OLLAMA_NUM_PARALLEL=2`、`KV_CACHE_TYPE=q8_0`、`FLASH_ATTENTION=1`、`KEEP_ALIVE=24h`；`.env` 配 `num_predict` 限制输出长度。
- **反思**：远程 LLM 的并发与资源是硬约束，上线前就要做压测，别等用户报告超时。

### 4.9 云端 API TLS 偶发不稳定

- **现象**：云端 API 偶发 TLS 超时/连接重置。
- **解决**：客户端加超时与重试；`USE_CLOUD_API` 开关可一键切回本地 Ollama。
- **反思**：多通道（云 API + 本地/远程 Ollama）切换能力是部署层面的"保险丝"，很值得保留。

### 4.10 前端工具链小坑

- **现象**：Vite dev server 别名 `.vue` 解析失效；Swagger 文档本地路径打不开；切换标签页聊天内容丢失。
- **解决**：修别名配置重启验证；Swagger 路径本地化（commit `4fe98de`）；KeepAlive 缓存页面组件 + `onActivated` 恢复滚动（commit `3c004b0`、`a1979cf`）。
- **反思**：前端工程化（别名、缓存、状态保活）要在脚手架阶段配好，别等项目中期再补。

### 4.11 部署与数据文件误入库

- **现象**：`backend/backend/data/canteen.db`、`metrics.json` 等运行时产物被 git 跟踪。
- **解决**：完善 `.gitignore`，删除仓库里的嵌套目录与产物（commit `69678a2`、`31f20e4`）。
- **反思**：`.gitignore` 应该从建库第一天就写全（`*.db`、`metrics.json`、日志、`__pycache__`、`.env`、node_modules）。

## 5. 如果再做一次，会怎么改

1. **路径与环境变量收敛到单一模块**：所有相对路径、`.env` 加载、DB 位置统一由一个 `config.py` 管理，杜绝 `backend/backend` 这类问题。
2. **先定"真流式"再写前端**：一开始就上 `astream_events`，避免模拟流式的返工。
3. **数据层先做幂等迁移框架**：任何 schema 变更都走可重复执行的迁移脚本，并保留"任意旧版本→最新"的升级测试。
4. **把后端接口契约测试前置**：前后端并行开发时用契约测试（现有 `frontend/src/**/*.test.ts` 已覆盖），避免联调期才发现字段不一致。
5. **远程 LLM 资源压测前置**：部署前先测并发与输出上限，把 `num_predict`、并行数、keep_alive 调优写在 DEPLOY 文档里。
6. **评审标准对照做清单**：把"及格→优秀"的标准拆成开发阶段的检查项（不崩、边界、HITL、中间件、Token 统计、子 Agent、MCP、Store、Skill、SUMMARY），每完成一档就打勾，避免后期补材料。
