# 推荐评分公式说明

> 版本：v1.3　|　日期：2026-08-03
> 实现文件：`backend/tools/scoring.py`、`backend/tools/optimizer.py`
> 所有者：A · 数据与算法
> 本文件为评分公式与组合优化算法的唯一权威说明，代码中的系数与本文件保持一致。

---

## 1. 评分公式总览

```
Score = W_budget × S_budget + W_nutrition × S_nutrition + W_pref × S_pref
```

| 分项 | 权重 | 说明 |
|------|------|------|
| W_budget | **0.35** | 预算约束（价格 ≤ 预算） |
| W_nutrition | **0.40** | 营养均衡（热量/蛋白质/碳水/脂肪 相对目标值的偏离度） |
| W_pref | **0.25** | 偏好权重（口味标签 + 荤素类别） |

> 权重之和 = 1.0。营养均衡权重最高（0.40），体现"健康优先"的产品定位；
> 预算 0.35 保证推荐结果在用户可承受范围内；偏好 0.25 提升个性化体验。

---

## 2. 预算约束 S_budget

**定义**：价格是否在预算内，超出预算线性衰减。

```
S_budget = 1.0                          ,  price ≤ budget 或 budget ≤ 0（无约束）
S_budget = max(0, 1 - (price-budget)/(2×budget))  ,  price > budget
```

**行为说明**：
- 价格在预算内 → 满分 1.0
- 超出预算 2 倍以上 → 得分为 0
- 预算为 0 或未设置 → 视为无预算约束，恒为 1.0

**示例**：预算 10 元
- 红烧肉 12 元 → S_budget = 1 - 2/20 = 0.9
- 米饭 1 元 → S_budget = 1.0
- 葱爆羊肉 15 元 → S_budget = 1 - 5/20 = 0.75

> **硬约束（@tool recommend）**：`recommend` 工具在打分前会先排除价格 > 预算的菜品，
> 保证返回结果全部满足"价格 ≤ 预算"。

---

## 3. 营养均衡 S_nutrition

**定义**：各营养指标相对「类别目标值」的偏离度越小，得分越高。

```
S_nutrition = 1 - Σ (w_goal[n] × deviation_n)
deviation_n = min(|actual_n - target_n| / target_n, 1.0)
```

### 3.1 类别营养目标值（一份食堂份量）

| 类别 | 热量(kcal) | 蛋白质(g) | 碳水(g) | 脂肪(g) |
|------|-----------|-----------|---------|---------|
| 荤菜 | 350 | 22 | 15 | 20 |
| 素菜 | 120 | 8 | 12 | 6 |
| 汤 | 90 | 8 | 8 | 5 |
| 主食 | 250 | 6 | 45 | 2 |
| 水果 | 80 | 1 | 20 | 0.3 |
| 饮品 | 80 | 3 | 12 | 2 |

### 3.2 营养目标权重（按 health_goals 调整）

不同健康目标下，各营养指标的重要性不同：

| 目标 | 热量 | 蛋白质 | 碳水 | 脂肪 |
|------|------|--------|------|------|
| （默认） | 0.25 | 0.25 | 0.25 | 0.25 |
| 高蛋白 | 0.15 | **0.50** | 0.15 | 0.20 |
| 增肌 | 0.15 | **0.55** | 0.15 | 0.15 |
| 控油 | 0.20 | 0.20 | 0.15 | **0.45** |
| 控糖 | 0.20 | 0.20 | **0.45** | 0.15 |
| 减脂 | **0.35** | 0.25 | 0.15 | 0.25 |

**示例**：控油目标下
- 红烧肉（脂肪 35g，目标 20g）→ 脂肪偏离度 = 15/20 = 0.75，贡献 0.45×0.75 = 0.34
- 清炒小白菜（脂肪 4g，目标 6g）→ 脂肪偏离度 = 2/6 = 0.33，贡献 0.45×0.33 = 0.15
- 素菜整体营养得分更高 → 符合控油推荐逻辑

## 4. 偏好权重 S_pref

```
S_pref = W_flavor × S_flavor + W_category × S_category
W_flavor = 0.6, W_category = 0.4
```

### 4.1 口味标签匹配 S_flavor

```
S_flavor = 命中用户偏好口味的标签数 / 用户偏好口味总数    （有偏好时）
S_flavor = 0.5                                             （无偏好时取中性）
```

**示例**：偏好 "清淡"，菜品标签 "清淡" → 1.0；标签 "辣" → 0.0

### 4.2 荤素类别偏好 S_category

```
S_category = 1.0  (目标为减脂/控油 且 类别=素菜)
S_category = 0.3  (目标为减脂/控油 且 类别≠素菜)
S_category = 0.5  (无特定类别偏好)
```

> 减脂/控油目标下偏好素菜，体现"清淡饮食"导向。

## 6. 系数设定依据

### 6.1 总体权重（W_budget / W_nutrition / W_pref）

| 权重 | 值 | 设定依据 |
|------|-----|----------|
| W_nutrition | 0.40 | 产品定位"健康食堂点餐参谋"，营养优先；偏离度惩罚保证推荐均衡 |
| W_budget | 0.35 | 学生用户对价格敏感，预算需强约束；但略低于营养体现"健康>省钱" |
| W_pref | 0.25 | 个性化口味是加分项，但不主导结果，避免"只推爱吃的" |

> 三者之和恒为 1.0，保证 Score ∈ [0, 1]，可跨菜品比较。

### 6.2 类别营养目标值设定依据

- 参考《中国居民膳食指南（2022）》每日摄入建议，换算到"一份食堂份量"：
  - 荤菜：一份约 150–200g 熟肉 → 蛋白质 22g、热量 350kcal 合理
  - 素菜：一份约 200g 熟菜 → 低热量 120kcal、蛋白质 8g
  - 主食：一份米饭/面条 150–200g → 碳水 45g、热量 250kcal
  - 汤：约 250ml → 热量 90kcal
- 各目标值允许 ±1 偏离（deviation 归一化到 0–1），不追求绝对值精确，只求"相对均衡"

### 6.3 营养目标权重（health_goals）设定依据

| 目标 | 强调指标 | 权重 | 依据 |
|------|----------|------|------|
| 高蛋白 | 蛋白质 | 0.50 | 蛋白质是饱腹感与肌肉合成关键 |
| 增肌 | 蛋白质 | 0.55 | 增肌期蛋白质需求最高 |
| 控油 | 脂肪 | 0.45 | 脂肪超限是热量超标的元凶 |
| 控糖 | 碳水 | 0.45 | 控制血糖波动主要看碳水 |
| 减脂 | 热量 | 0.35 | 热量缺口是减脂核心 |

## 7. 系数调整策略

| 场景 | 调整建议 |
|------|----------|
| 用户对价格极敏感 | W_budget 提到 0.45，W_nutrition 降到 0.30 |
| 产品定位"健康食堂" | W_nutrition 提到 0.50 |
| 强调个性化口味 | W_pref 提到 0.35 |
| 引入新营养指标（如膳食纤维） | 在 NUTRIENTS 中追加，并在各类别目标值补充对应数值 |

> 调整系数时须同步修改 `backend/tools/scoring.py` 中的 `WEIGHTS` 常量，
> 并更新本文档，保证代码与文档一致。

## 8. 完整计算示例（可复现）

用户画像：预算 15 元，偏好"清淡"，目标"控油"

以「清炒小白菜」为例逐步计算：

| 步骤 | 计算 | 结果 |
|------|------|------|
| S_budget | 4 ≤ 15，预算内 | 1.0 |
| S_nutrition | 脂肪偏差=2/6=0.33×0.45；热量偏差=40/120=0.33×0.20；蛋白质偏差=5/8=0.63×0.20；碳水偏差=7/12=0.58×0.15 → 1-(0.15+0.066+0.126+0.087) | 0.571 |

## 10. 组合优化算法（optimize_meal）

> 实现文件：`backend/tools/optimizer.py`　|　函数：`optimize_meal(dishes, budget, calorie_limit)`

### 10.1 问题定义

给定预算（元）与热量上限（kcal），从菜品库中选若干道菜组成一餐，约束与目标：

| 项 | 说明 |
|----|------|
| 约束1 | 总价格 ≤ 预算 |
| 约束2 | 总热量 ≤ 热量上限 |
| 约束3 | 荤素搭配合理：至少 1 荤菜 + 1 素菜 + 1 主食 |
| 目标 | 最大化蛋白质总量（高蛋白膳食导向） |

### 10.2 算法：二维 01 背包（动态规划）

```
状态：dp[price][calories] = 最大蛋白质(g)
转移：对每道菜（01背包，倒序遍历）:
      dp[p][c] = max(dp[p][c], dp[p-price][c-calories] + protein)
      同时用 choice[p][c] 记录达到该状态选择的菜品，用于回溯
```

- 复杂度：O(n × budget × calorie_limit)，n=菜品数
- 选满后回溯得到选中菜品集合
- 目标为蛋白质最大，兼顾高蛋白营养导向

### 10.3 荤素搭配修正

背包解可能缺某类别（如只有荤+汤+主食），通过 `_ensure_balance` 修复：

1. 先尝试**直接补足**缺失类别（有用户画像时选评分最高的菜，融合口味偏好；否则选蛋白质最高）
2. 若预算/热量不足，**尝试移除 1~2 道已选菜**后重新补足
3. 在全部可行方案中取**评分最高**（无画像时蛋白质最高）的平衡方案

> 有 `user_profile` 时补足选择调用 `scoring.score_dish`，使口味偏好（如"清淡""辣"）
> 影响荤素补足；`optimize_meal_tool` 的 `preferences` 参数即注入此路径。

### 10.4 返回结构

```python
{
    "dishes": [...],            # 选中菜品（完整信息）
    "total_price": 18.0,        # 总价格
    "total_calories": 760.0,    # 总热量
    "total_protein": 52.0,      # 总蛋白质
    "total_carbs": ...,         # 总碳水
    "total_fat": ...,           # 总脂肪
    "categories": {"荤菜":1, "素菜":1, "汤":1, "主食":1},  # 类别分布
    "budget": 20.0,             # 预算
    "calorie_limit": 800.0,     # 热量上限
    "balance_ok": True,         # 荤素搭配是否合理
    "reason": "荤素搭配合理（已补足）",
}
```

### 10.5 示例

预算 20 元、热量上限 800kcal：

| 菜品 | 类别 | 价格 | 热量 | 蛋白质 |
|------|------|------|------|--------|
| 红烧鸡腿 | 荤菜 | 10 | 320 | 30 |
| 麻婆豆腐 | 素菜 | 5 | 160 | 10 |
| 豆腐青菜汤 | 汤 | 2 | 60 | 5 |
| 馒头 | 主食 | 1 | 220 | 7 |
| **合计** | | **18** | **760** | **52** |

> 边界行为：预算或热量上限为 0 返回空；约束下无可行搭配时返回空并附原因；
> 热量上限过低（<300）时可能无法满足荤素搭配，如实返回 `balance_ok=False`。

## 12. 边界容错说明（D7）

| 模块 | 异常输入 | 行为 |
|------|----------|------|
| `budget_score` | 非数值价格 | 返回中性 1.0 |
| `nutrition_score` | dish=None / 空 | 返回 0 |
| `preference_score` | dish/user_profile=None | 返回中性 0.5 |
| `score_dish` / `score_dishes` | None 输入 | 返回零分/空列表 |
| `recommend` | budget<0、top_k≤0 | 回落到默认值 |
| `optimize_meal` | 空/None 菜品、非数值预算、≤0 约束 | 返回空结果 + reason |
| `get_weekly_trend` | 非法日期、天数≤0 | 回退今天 / 默认7天 |

> 设计原则：数值型异常输入返回**中性分/空结果**（不抛异常，保证 Agent 链路稳定），
> 数据完整性类（如无效外键 dish_id）仍由 SQLite 外键约束拒绝。
