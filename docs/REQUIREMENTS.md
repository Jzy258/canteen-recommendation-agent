## 1. 项目概述

一个食堂点餐参谋（LLM Agent）：用户用自然语言对话，Agent 通过自研工具链（菜谱检索、营养评分、克重组合优化、天气、摄入记录、用户画像）给出荤素搭配合理的一餐推荐并持续记忆，用趋势页展示营养摄入变化。

目标用户：在校学生 / 食堂常驻就餐人员。

## 2. 功能列表（FR）

| 编号 | 功能 | 一句话说明 | 优先级 |
|---|---|---|---|
| FR-01 | 菜品营养查询 | 按菜名/关键词查热量、蛋白质、碳水、脂肪及参考来源 | P0 |
| FR-02 | 营养库建设 | 100 道菜结构化入库，字段含热量/蛋白质/碳水/脂肪/价格/口味/荤素/克重 | P0 |
| FR-03 | 菜单采集入库 | 多天×餐次食堂菜单结构化入库 | P0 |
| FR-04 | 推荐评分 | 按预算约束、营养均衡、偏好权重计算推荐分并返回候选 | P0 |
| FR-05 | 推荐理由生成 | 推荐结果附理由（如"蛋白质达标且不超过预算"） | P0 |
| FR-06 | 多日饮食追踪 | 记录每餐摄入（HITL 确认后写入），按天/周输出营养趋势 | P1 |
| FR-07 | 搭配优化子 Agent | 给定预算+热量上限，用组合优化求最优一餐搭配 | P1 |
| FR-08 | 天气 MCP 接入 | 通过高德天气获取温度，天冷推热汤面、天热推清淡 | P2 |
| FR-09 | 用户系统 | 注册/登录（JWT + PBKDF2），多用户数据隔离 | P1 |
| FR-10 | 管理员 API | 维护菜品库、菜单、查看统计（/admin/*） | P1 |
| FR-11 | 偏好设置 | 预算范围、口味、忌口/过敏、健康目标（标签输入+预设） | P1 |
| FR-12 | 克重调控 | 菜品份量克重与每餐克重记录，精确营养计算 | P1 |
| FR-13 | 菜单页 | 按日期/餐次浏览食堂菜单并筛选菜品 | P2 |
| FR-14 | 今日工作台 | 首页概览今日菜单、天气、快捷推荐 | P2 |

### 优先级划分

- **P0（必须，保底）**：FR-01 ~ FR-05 —— 对应及格/中等档
- **P1（重要）**：FR-06、FR-07、FR-09 ~ FR-12 —— 对应良好档
- **P2（亮点）**：FR-08、FR-13、FR-14 —— 对应优秀档

## 3. 用户使用场景

| 场景 | 谁 | 在什么情况下 | 用哪个功能 |
|---|---|---|---|
| SC-01 问菜 | 就餐者 | 想知道"红烧肉热量多少" | FR-01 |
| SC-02 求推荐 | 就餐者 | 说"预算 20 以内、想吃清淡点" | FR-04/05/11 |
| SC-03 打卡记录 | 就餐者 | 吃完想记录今天午餐 | FR-06（HITL） |
| SC-04 看趋势 | 就餐者 | 想复盘近一周蛋白质够不够 | FR-06 趋势 |
| SC-05 优化搭配 | 就餐者 | 给定预算+热量上限求最优搭配 | FR-07 |
| SC-06 天气吃饭 | 就餐者 | 下雨天想喝热汤 | FR-08 |
| SC-07 登录/隔离 | 就餐者 | 换人使用，各自偏好不串 | FR-09 |
| SC-08 管数据 | 管理员 | 新增菜品、改菜单、看统计 | FR-10 |
| SC-09 设定偏好 | 就餐者 | 首次使用填预算/忌口/健康目标 | FR-11 |
| SC-10 减重精确 | 就餐者 | 想按克重控制摄入 | FR-12 |

## 4. 非功能需求（NFR）

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-01 | 可用性 | 空输入给提示；工具/LLM 异常给友好反馈，不抛 traceback |
| NFR-02 | 对话能力 | 多轮对话有记忆；会话历史、多会话隔离；真实流式输出 |
| NFR-03 | 安全 | 密钥走 `backend/.env`，不入库不提交；JWT 鉴权 |
| NFR-04 | 可观测 | 中间件记录日志、耗时、Token 统计 |
| NFR-05 | 健壮性 | 超出能力范围如实说明；工具异常可恢复；流式失败回退非流式 |
| NFR-06 | 合规 | 营养数据注明参考来源；保留数据清洗记录 |
| NFR-07 | 可维护 | 文档齐全（README/DESIGN/REQUIREMENTS/DEPLOY/ANALYSIS/SUMMARY） |
| NFR-08 | 部署 | Docker Compose 一键启动；远程 LLM 服务器可切换 |

## 5. 验收对照（评分标准）

| 档位 | 本需求对应项 | 落地状态 |
|---|---|---|
| 及格 | FR-01~03、NFR-03 | 完成，Agent 链路通 |
| 中等 | FR-04~05、NFR-01/02 | 完成，多工具+多轮记忆 |
| 良好 | FR-06、HITL 审批、中间件、数据清洗记录、边界处理 | 完成 |
| 优秀 | 子 Agent、MCP、Store 长期记忆、Token 统计、流式、会话隔离、SUMMARY | 完成（详见 SUMMARY） |

## 6. 范围与约束

- **不做**：真实下单支付、多食堂跨库、深度学习调优。
- **技术约束**：LLM 用 OpenAI 兼容 API（云端 API / 本地 Ollama 可切换）；工具与 RAG 链路自研。
- **数据约束**：营养数据以《中国食物成分表》等公开来源为参考，注明出处。
