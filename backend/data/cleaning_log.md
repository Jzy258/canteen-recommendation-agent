## 2. 清洗流程

### 2.1 字段完整性检查

检查每行是否包含全部9个预期字段：

```
name, calories, protein, carbs, fat, price, category, flavor_tags, source
```

**结果**：54条全部字段完整，无缺失字段。

### 2.2 名称规范化

处理规则：

| 规则 | 处理方式 | 示例 |
|------|----------|------|
| 去除首尾空格 | `strip()` | `" 红烧肉 "` → `"红烧肉"` |
| 全角转半角 | 全角空格替换 | `"红烧　肉"` → `"红烧肉"` |
| 去除中间空格 | 删除所有空格 | `"酸辣 土豆丝"` → `"酸辣土豆丝"` |

**结果**：54条名称格式规范，无需修改。

### 2.3 重复检测

- **完全重复检测**：名称完全相同的记录，保留第一条，后续跳过
- 入库时 `INSERT OR IGNORE` 双重保障

**结果**：无完全重复记录。

### 2.4 数值字段清洗

| 字段 | 单位 | 有效范围 | 处理策略 |
|------|------|----------|----------|
| calories | kcal/份 | 0–800 | 负值→绝对值；超上限→截断为上限；空值→0；非法字符→0 |
| protein | g/份 | 0–60 | 同上 |
| carbs | g/份 | 0–80 | 同上 |
| fat | g/份 | 0–50 | 同上 |
| price | 元/份 | 0–50 | 同上 |

**范围设定依据**：
- 热量上限800kcal：食堂一份荤菜约300–500kcal，一份炒菜约100–200kcal，一份主食约200kcal，总热量上限设为800可覆盖重油荤菜
- 蛋白质上限60g：一份大份荤菜蛋白质约20–30g，上限60g覆盖双份情形
- 碳水上限80g：一份主食碳水约45g，上限80g覆盖大份/双份主食
- 脂肪上限50g：一份红烧肉脂肪约35g，上限50g覆盖重油菜品
- 价格上限50元：食堂单品价格通常不超过30元，上限50元预留安全余量

**结果**：54条数值均在有效范围内，无异常值。

### 2.5 分类校验

有效分类集合：`{荤菜, 素菜, 汤, 主食, 水果, 饮品}`

不在集合中的分类自动修正为"素菜"（保底分类）。

**结果**：54条分类全部在有效集合内。

### 2.6 来源标注

每条数据须注明营养参考来源，缺失时标记为"待补充"。

**结果**：54条均标注来源为"中国食物成分表第6版"。

## 4. 清洗脚本验证结果

用7条脏数据验证清洗脚本的处理能力，全部场景正确识别并处理：

| 脏数据类型 | 输入 | 处理后 | 处理方式 |

## 7. 脚本使用方式

```bash
# 仅检查不修改（查看报告）
python backend/data/clean.py --check

# 检查并覆盖写入（清洗后写回原文件）
python backend/data/clean.py

# 指定输入输出文件
python backend/data/clean.py --input raw_dishes.csv --output clean_dishes.csv
```
